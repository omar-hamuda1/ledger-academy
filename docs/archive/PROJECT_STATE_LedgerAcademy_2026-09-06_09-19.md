# Project State — Ledger Academy

Last updated: 2026-09-06 (full security/correctness/quality audit)

## 1. Architecture & Tech Stack

- **Framework**: Next.js 16 (App Router) + TypeScript, React 19
- **Styling**: Tailwind CSS v4 (CSS-based config, no `tailwind.config.ts`), Cairo font for Arabic
- **Database**: **Postgres on Neon** (project `late-tree-77912979`). `DATABASE_URL`/`DATABASE_URL_UNPOOLED`/`NEON_BRANCH` live in `.env` (Neon-managed); app secrets live in `.env.local`. No migration history — schema changes go through `prisma db push`.
- **ORM**: Prisma v6.19.3 (classic CLI — do not upgrade to the v8 "Prisma Developer Platform" line, it has a completely different, incompatible CLI with no `migrate`/`generate` commands)
- **Auth**: NextAuth v4 (`next-auth` + `@next-auth/prisma-adapter`), credentials provider, JWT sessions, role (`ADMIN`/`INSTRUCTOR`/`STUDENT`) baked into the session
- **Payments**: Stripe (`stripe` SDK), Checkout Sessions + webhook, currency **EGP**
- **Icons**: `lucide-react` (v1.x — note: this version dropped brand/social icons like Facebook/Instagram/YouTube; hand-rolled SVGs live in `src/components/ledger-academy/SocialIcons.tsx`)
- **Validation**: Zod on every API route
- Runs from `Mansa 1/accounting-elearning/` (the parent folder name has a space, which is why the app itself lives in a subfolder — `npx create-next-app` rejects a directory named "Mansa 1" directly)

## 2. Platform Purpose

**Ledger Academy** — an Arabic (RTL), dark-navy-and-gold themed e-learning platform teaching **Business Administration (إدارة الأعمال)** to Egyptian secondary-school students (3 grade levels: الصف الأول/الثاني/الثالث الثانوي). Content is presented by "محمد حسين," who holds the platform's `ADMIN` role.

**Hard rule**: the word "مدرس" (teacher) must never appear anywhere in the UI. Use **"محاضر"** (lecturer) or "مدرب" instead. This has been enforced everywhere (dashboard titles, marketing copy, etc.) and verified via full-codebase grep.

Switched course thumbnails to `next/image` (verified it actually optimizes/resizes remote images, not just passes them through) — required allowing any HTTPS host in `next.config.ts` since thumbnails are arbitrary admin-supplied URLs.
- **Full security/correctness/quality audit (2026-09-06)**: ran a 3-way parallel audit (security/authorization, correctness/data-integrity, code quality) covering every API route and the Prisma schema, verified every finding by reading the actual code myself, then fixed everything real-world-exploitable:
  - **Fixed — payment bypass**: `POST /api/enrollments` let any logged-in user enroll in any paid course with zero price check, completely bypassing Stripe. It was unused by any UI (checkout already handles enrollment correctly), so it was deleted outright rather than patched.
  - **Fixed — quiz answer-key leak / paywall bypass**: `POST /api/quizzes/[id]/attempts` never checked the caller was enrolled, so any user could take any quiz (including unpurchased courses') and the response handed back `correctId` for every question. Now checks enrollment first.
  - **Fixed — progress IDOR**: `POST /api/progress` accepted any `lessonId` with no ownership check, letting a user fabricate completion/watch-time for lessons in courses they never bought. Now checks enrollment first.
  - **Fixed — cross-course content leak**: the lesson-detail page verified enrollment in the course matched by the URL's `slug`, but then fetched the lesson purely by `lessonId` with no check it actually belonged to that course — so a student enrolled in one (even free) course could view any paid course's lesson content by URL-guessing/observing a `lessonId`. Now the lesson query is scoped to the resolved course.
  - **Fixed — delete-lesson/module crash**: `LessonProgress`/`Quiz` foreign keys to `Lesson` are `ON DELETE RESTRICT`; deleting a lesson or module that any student had touched (progress row) or that had a quiz attached threw an uncaught 500 with the admin UI just silently doing nothing. Both delete routes now clean up `QuizAttempt`→`Quiz` and `LessonProgress` in a transaction first (mirrors the pattern the quiz-delete route already used correctly).
  - **Fixed — OTP resend confusion**: requesting a second OTP code and then entering the first email's code failed (verify only ever checked the newest row) and burned an attempt on the wrong row. `otp/send` now deletes prior unverified codes for that email+purpose before issuing a new one.
  - **Fixed — Stripe double-charge risk**: checkout session creation had no idempotency key, so a rapid double-click could create two separately-payable Stripe sessions. Added a per-user/per-course/per-minute idempotency key.
  - **Fixed — lesson/module order collisions**: new lesson/module `order` was computed as `array.length + 1`, which re-mints a colliding value after a middle item is deleted. Now uses a `_max` aggregate instead.
  - **Fixed — inconsistent error language**: ~15 API route files had English guard-clause errors ("Forbidden", "Unauthorized", "Invalid input.", etc.) shown directly to Arabic-speaking users; all translated.
  - All of the above verified with real exploit attempts against the running app (not just read-through) — e.g. actually tried the cross-course lesson access and confirmed it now 404s instead of leaking content, actually deleted a module with real progress/quiz-attempt rows attached and confirmed no crash and no orphaned rows.
  - **Resolved with user**: two junk test courses were confirmed as accidental real data entry and deleted (with full cascade cleanup, verified no orphaned rows). The previous dated snapshot was corrected in place to match current reality rather than deleted, per the user's preference to keep the dated record.
  - **Larger optional cleanup identified but not done (needs a scope decision)**: the register/forgot-password OTP flow pages share a lot of near-duplicate code (candidate for extraction, same pattern as `CourseCard.tsx`); admin form input styling is copy-pasted across ~7 components instead of a shared `Input` component; `LedgerHeader.tsx` (the single most-reused component) and `EnrollButton.tsx` and `CreateCourseForm.tsx` are still on the pre-design-system tokens (`amber-400`/`slate-950`/`rounded-2xl`) while `EditCourseDetailsForm.tsx` (same conceptual form) is fully migrated — causes visible style mismatch between "New Course" and "Edit Course" admin screens.

## 4. Pending / Known Gaps

- **Email OTP only reaches the account owner, not real students**: Resend is connected and working (`RESEND_API_KEY`/`EMAIL_FROM` set, real emails confirmed delivered), but using the shared `onboarding@resend.dev` sender, which Resend restricts to delivering only to the account's own verified email. Sending to arbitrary student emails needs one of: (1) SendGrid single-sender verification (verify one email, no domain, free tier — recommended), (2) Gmail SMTP via app password (free, ~500/day cap, more spam risk), or (3) buy a real domain (~$10–15/yr) and verify it with Resend. **User explicitly deferred this decision on 2026-09-06** — ask which option before doing any of them.
- **Old SQLite data not migrated**: `prisma/dev.db` still has 3 extra users, an extra lesson, and a quiz built by hand during earlier testing that never made it into the new Postgres database — ask before deciding to migrate or discard it.
- **Lesson-player double sidebar**: `/dashboard/student/courses/[slug]/[lessonId]` renders both the role-based `DashboardShell` sidebar and the course-navigation `LessonSidebar` — functional but visually redundant. Would need restructuring the route outside the `dashboard/student` layout tree to fix properly.
- **No "delete quiz" UI**: `DELETE /api/quizzes/[id]` exists (admin-only) but nothing in the admin UI calls it — only individual questions can be deleted via the UI.
- **Test/sample video**: all lesson `videoUrl`s point to a public Google Cloud sample clip (`ForBiggerBlazes.mp4`, ~15s, Creative Commons) as a placeholder — needs real course footage before launch.
- **Stripe is test-mode only**: needs the business-verification step in the Stripe Dashboard, live-mode keys, and a permanent webhook endpoint (Dashboard → Webhooks, not the CLI listener) before real charges can be accepted.
- **No real imagery anywhere**: `public/` still only has the default Next.js starter SVGs — no course thumbnails (the `Course.thumbnailUrl` field now works end-to-end via the admin edit form, but no admin has set one yet), no instructor photo (still a generic `<User>` icon in a gradient circle standing in for محمد حسين). Needs real photos/thumbnails supplied by the user — can't be fabricated.
- **No module/lesson reordering UI**: `order` fields exist on `Module`/`Lesson` and are respected everywhere they're read, but there's still no drag/reorder or move-up/move-down control — new items always append at the end. Module create/delete now exists (this session); reordering does not.
- **No user role management**: `/dashboard/admin/users` is still read-only (view name/email/role) — no promote/demote, disable, or manual-enrollment UI. The `SiteSettings`-style admin-control pattern established this session (a real settings model + form) is the template to follow if this gets built.
- **No search/filter** on any admin list (pagination was added this session; search/filter within a page is still missing) — fine at current scale, will need it as the user base grows.
- **Rate limiting is still in-memory**, not shared across server instances. Fine for a single-instance deployment; needs a shared store (e.g. Upstash Redis) before horizontally scaling to handle real concurrent traffic. Deliberately not done yet — needs a provider decision first.
