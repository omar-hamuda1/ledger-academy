## 1. What shipped this session (newest first)

### Database workflow — Prisma Migrate adopted (`6d5ee5b`, `c450e97`)
- Was: `prisma db push`, no history, manual push to prod every schema change.
- Now: `prisma/migrations/` committed, baseline `0_init` (verified 3 ways —
  shadow-DB replay == schema, test DB == schema, prod DB == schema). Both Neon
  branches baselined with `migrate resolve --applied 0_init` (0 steps run).
- `vercel.json` `buildCommand` = `prisma migrate deploy && prisma generate && next build`
  → migrations apply to prod automatically during each Vercel deploy.
- **New schema-change workflow (in `CLAUDE.md`):**
  ```
  # edit prisma/schema.prisma, then:
  set -a && . ./.env.test && set +a && npx prisma migrate dev --name <short_desc>
  ```
  **Must source `.env.test` first** — otherwise `prisma.config.ts`'s
  `import "dotenv/config"` loads `.env` and `migrate dev` runs against
  **production**. Commit the generated migration folder with the code. CI is
  unchanged (builds/tests the already-migrated test branch).

### Security — CSP now enforcing (`876c507`, `02d72d2`)
- `next.config.ts`: HSTS (`max-age=1y; includeSubDomains`) + a full CSP.
- Shipped Report-Only, verified clean on the live site (home / course /
  lesson-with-video / dashboard), then flipped to **enforcing** 2026-09-08.
- `script-src` allows `www.youtube.com` (IFrame API). To add a host later:
  switch the header key back to `Content-Security-Policy-Report-Only`, add the
  host, re-verify in the browser console, re-enforce.

### Video — watch-based progress (`d8200c5`)
- `VideoPlayer.tsx` is now a **client** component. Auto-reports `watchedSec`
  (throttled), **auto-completes a lesson at ≥90% watched**, and **resumes**
  playback where the student left off.
- Works for direct `.mp4` files and YouTube (IFrame API). Other embeds render
  untracked. `MarkCompleteButton` kept as a manual fallback.
- `POST /api/progress` made **monotonic** (watchedSec only grows; a completed
  lesson can't be un-completed) + rate-limited (150 / 5 min / user).
- No schema change (`LessonProgress.watchedSec` already existed).

### In-lesson Q&A (`cded2c6`)
- New `LessonQuestion` + `LessonAnswer` (cascade from the lesson). Admin
  answers flagged `byInstructor` → "المحاضر" badge.
- Enrolled-student-or-admin participation. Routes: `POST /api/lessons/[id]/questions`,
  `POST /api/lesson-questions/[id]/answers`, `DELETE` on both
  `/api/lesson-questions/[id]` and `/api/lesson-answers/[id]` (own, or any as
  admin — admin deletes audit-logged).
- New question → notifies all admins. New answer → notifies the asker.
- `LessonQA.tsx` on the student lesson player **and** the admin lesson editor.

### Course ratings + reviews (`4c57c5d`)
- New `Review` (one per user+course, 1–5 + optional text, `hidden` moderation
  flag). `POST /api/reviews` upserts (enrolled only). `PATCH`/`DELETE
  /api/reviews/[id]` for admin hide/unhide + delete.
- Course page: rating chip in the hero + a "قيّم هذا الكورس" form for enrolled
  students + a reviews list. `src/lib/reviews.ts`, `Stars.tsx`.

### Per-course drop-off analytics (`5c92fa0`)
- `/dashboard/admin/courses/[id]/insights` — enrolled / never-started /
  completed-all counts, a per-lesson completion funnel (biggest drop
  auto-flagged red), a quiz table (attempts / avg score / pass rate).
- Read-only aggregation, no schema change. `src/lib/course-insights.ts`.
- Linked from the courses list (chart icon) + the course edit page.

### Un-enroll / refund (`23d5d8e`)
- `POST /api/courses/[id]/unenroll { userId }` (admin) — hard-deletes the
  enrollment + that course's `LessonProgress`/`QuizAttempt` for the user, in a
  transaction. Audit `enrollment.remove`.
- Roster table + per-row "إزالة" on the course edit page (`CourseRoster.tsx`).
- Previously the only way to revoke access was disabling the whole account.

### Completion certificates (`0b595c7`, `efaef0d`)
